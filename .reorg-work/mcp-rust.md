# MCP in Rust

Companion to `README.md` (rules for this dir, working rules, end state). Everything about this step lives here; the README section is a pointer.

_Status: executed._

The MCP server moves from the TS package `@carlwr/zshref-mcp` into the `zshref` crate as a second binary, `zshref-mcp`, behind the `mcp` feature; the TS package, its workflow and CI jobs go. One tool implementation, two adapters in one crate.

## Scope

- `src/lib.rs`: library target for both binaries (`cli`, `corpus`, `tools` public; no API stability); `src/main.rs` → `zshref`, `src/bin/zshref-mcp.rs` → `zshref-mcp` (`required-features = ["mcp"]`)
- shared request path `tools::call` = validate against `inputSchema` → fill its defaults → `dispatch`; `batch` and the MCP server use it, the CLI reaches `dispatch` directly (clap has done both); `tools::input` holds the two steps; `ToolDefs::get` replaces the per-site lookups
- rmcp 3.3 (`default-features = false`, `server` + `transport-io`), tokio current-thread; hand-written `ServerHandler`: `initialize` (`instructions` = tooldef preamble, `capabilities.tools`), `tools/list` (name, description, `inputSchema`, `outputSchema` from tooldef, in tooldef order), `tools/call` (text block + `structuredContent`; unknown tool and invalid input as `isError` without it); nothing else
- `zshref-mcp` keeps `--help` / `--version` / TTY-hint; `--version` is the CLI's block with the bin name swapped (`cli::version_string` shared)
- `tests/mcp.rs`: black-box stdio client; every `mcp-stdio.test.ts` and `cli.test.ts` assertion ported and strengthened (`tools/list` == tooldef.json field by field; every successful call: `structuredContent` == parsed text, validated against `outputSchema` via `tests/common`; pipelined pair; schema default on omitted `limit`; three invalid-input messages; EOF before and after the handshake → exit 0, empty stderr)
- `tests/msrv.rs` resolves `--all-features`; `make cli-test` / `cli-vendored-test` / `cli-clippy` / `cli-package` run `--all-features`; `make cli` / `cli-debug` unchanged (the default binary's dependency set is the CLI's alone)
- `THIRD_PARTY_NOTICES.md` generated by `zshref-rs/scripts/third-party-notices`; `probe-opencode` ported to `zshref-rs/scripts/`
- deleted: `packages/zshref-mcp/`, `release-zshref-mcp.yml`, the `mcp` CI job and its registry/bootstrap lines, root `jsrREGISTRY:mcp:*`, tooldef's `adapter-matrix.ts` + test (empty after the row removal)
- docs: tool documentation and client configuration → `zshref-rs/README.md` §MCP server; user-facing links to `carlwr/zshref-mcp` re-pointed to `carlwr/zshref`; tool-naming rationale → tooldef `DEVELOPMENT.md` (interim; goes with tooldef)
- untouched: the embedded tooldef metadata (ownership moves in the tooldef step); `parity.test.ts`; the extension

## Decisions

- _MSRV:_ `rust-version` rises 1.85 → 1.88 — rmcp's floor; one floor for every `cargo install` form rather than a per-feature MSRV
- _`tools/call` text block:_ compact JSON (rmcp's `CallToolResult::structured`); the TS server pretty-printed. `structuredContent` is the schema-aware payload; the text block is the fallback and agents pay per token
- _`isError: false` on success:_ rmcp emits it; the TS server omitted it. Spec-conformant either way
- _validation stays ours:_ rmcp validates input only through `get_tool` (left at its `None` default); `tools::call` validates and fills defaults exactly as `batch` does, so the two adapters cannot drift
- _EOF before the handshake:_ exit 0, silent (`ServerInitializeError::ConnectionClosed`) — a client that spawns and closes is not an error; other handshake failures are fatal (exit 1)
- _flags:_ hand-rolled matching over clap — two flags, no option-arguments; recorded beside the code
- _distribution:_ `cargo install zshref --features mcp`; Homebrew formula unchanged (decide `--features mcp` at extraction — `EXTRACTION.md`)
- _crates.io keywords:_ `documentation` → `mcp`
- _notices:_ generated from `cargo tree -e normal,no-proc-macro --all-features` over the msrv triples, grouped by the declared license string as-is (`Apache-2.0 OR MIT` and `MIT OR Apache-2.0` stay distinct)

### Decided during execution

- `tools/list` order is asserted equal to tooldef order, not merely the set of names
- the workflow example in `cli/prose.rs` goes through `tools::call` (it needed the `limit` default); the other help examples pass complete inputs and stay on `dispatch`
- `#[allow(dead_code)]` on `Index` fields dropped: `pub` fields of a library type are never dead
- the "thin adapter" narrative (root `AGENTS.md`, tooldef docs, `DESIGN.md`) reduces to the scope fence: a Rust adapter over exported JSON has no imports to fence
- the TS package was tooldef's only workspace dependent; without it `upstreamPkgs` is zsh-core alone, `pnpm bootstrap:upstream` stopped rebuilding tooldef and `make artifacts` no longer refreshed `tooldef.json`
  - found by the staleness pass; the gates had the artifacts on disk
  - `upstream-ready.mjs bootstrap` takes package names; `make artifacts` passes tooldef; the line goes with tooldef
