# AGENTS.md — `zshref-web`

Static SPA: NLP search over zsh-core records — plus the Node-side NLP toolchain that builds its artifacts and evaluates its ranking. Workspace member, private, not published.

## Stack

- SvelteKit 2 + Svelte 5, `adapter-static` (`svelte.config.js`) — prerendered static HTML+JS+CSS, `index.html` fallback
- TypeScript (strict + `noUncheckedIndexedAccess`), Vitest; Biome for `.ts`, svelte-check for `.svelte` — its include reaches `nlp/` and `scripts/` too (`svelte.config.js`)
- `@huggingface/transformers` — one embedder, one model (BGE-small): ORT-Web in the browser (`src/lib/embedder.ts`), `onnxruntime-node` on the Node side (`nlp/embedder-node.ts`)
- `markdown-it` + `shiki` (dual light/dark theme via CSS variables) for record markdown
- `zod` — artifact schemas at load time; also the source of truth for the editor schemas of the rules YAML, the sentence fixture and the QA corpus
- self-hosted variable fonts via `@fontsource-variable/*`

Alternatives ruled out: React / Elm / PureScript front-ends; per-record SSG (records are dynamic at runtime); a Rust ranker compiled to WASM (the NLP is TS end-to-end: one language, one embedder); in-browser index building (too slow for first load).

## Layout: the browser/Node seam

- `src/` — the browser bundle: routes, components, `src/lib/{artifacts,embedder,search}.ts`, the ranker under `src/lib/ranker/`
- `nlp/` — the Node side: everything that reads the corpus or the model; the evals under `nlp/eval/`
  - `nlp/rules/` — the editable rules YAML, the sentence fixture, their editor schemas
  - `nlp/data/` — committed generated JSON (regenerated by the `UPDATE_*` tests) and the QA corpus
  - every path: `nlp/paths.ts`
- `scripts/` — the `tsx` entry points behind the `package.json` scripts, and `fetch-model`
- `tests/` — Vitest; `tests/nlp/` for the Node side

The seam is a static import fence, not a package boundary — `tests/import-fence.test.ts`:

- nothing under `src/` imports `@carlwr/zsh-core`, a Node builtin, the Node ONNX runtime, or a path leaving `src/`
- `nlp/` imports its types from `src/` — the sanctioned direction
- `vite build` is the fence's other half

Product search (`src/lib/search.ts`): embed (with embedding-only query expansion) -> `rank` with no resolver hit -> lookup-map promote of a canonical-identifier query to slot 0.

## Upstreams

Two, both pinned:

- **`@carlwr/zsh-core`** at build time — `workspace:*`; corpus, taxonomy, resolver
  - every script reading it carries a `pre*` hook -> `upstream-ready.mjs ensure` (`PACKAGING.md`; `BZ_SKIP_UPSTREAM`: root `AGENTS.md`)
  - the browser bundle is zsh-core-free: the index carries each record's markdown body
- **Hugging Face Hub** at runtime — the browser embedder downloads the model on first visit
  - model id: `MODEL_ID` in `src/lib/embedder.ts`; `scripts/fetch-model` repeats it, drift-checked by a test
  - the revision is pinned in `scripts/fetch-model` only; the browser pipeline names none

## Model and artifacts

Both gitignored:

- `scripts/fetch-model` -> `.aux/model/` — idempotent; the one input not reproducible from the repo; what every reporter needs (a missing or stale index is built in memory, never written)
- `pnpm build:index` -> `static/artifacts/` — what `src/lib/artifacts.ts` fetches under `/artifacts`: the index, the rules JSON, categories, lookup map
  - an index that still validates against the corpus is kept; `--force`, `--validate`: `--help`
  - a rebuild embeds the corpus: minutes on CPU
  - the rules YAML is the editable form; the JSON is build output

## Tests

The package-specific part of `TESTING.md`:

- `pnpm test` is model-free by default: a test needing a gitignored input (`STAGED` in `nlp/paths.ts`) skips via `artifactGate` (`tests/_helpers.ts`)
  - `pnpm run test --reporter=verbose` prints the reason (bare `pnpm test` hands `--reporter` to pnpm itself)
  - committed inputs get no gate: their absence is a defect
- `BZ_REQUIRE_WEB_ARTIFACTS=1` flips skip -> fail
  - the CI `nlp` job (`.github/workflows/ci.yml`) sets it after fetching the model and building the index; not part of `integration`
  - rehearse that job locally: `ACT_JOB=nlp scripts/test-integration-act` from the repo root (VM sizing: root `DEVELOPMENT.md`)
- `BZ_NLP_SLOW=1` additionally runs the full mechanical report (minutes); CI stays at the capped smoke
- every reporter is spawned ungated for its argument handling and, gated, run on a capped bench (`tests/nlp/reporters.test.ts`)

## Parity and sanity fixtures

TS goldens generated by `nlp/fixtures.ts`; two tiers with disjoint failure modes:

| | parity-fixture | sanity-fixture |
|---|---|---|
| isolates | ranker math only | full stack (embedder + ranker) |
| test | `tests/parity.test.ts` — the fixture's own miniature index + `queryVec` into `rank()`; no embedder, no staged inputs | `tests/sanity.test.ts` (product mode), `tests/nlp/fixtures.test.ts` (oracle mode) — below |
| pins | the ranker's f32 arithmetic against its own past | full-stack behaviour, coarser |
| failure means | ranker math diverged | embedder integration broke, or ranker drift |

The sanity fixture's two tests:

- product mode (`tests/sanity.test.ts`) — the browser `embedQuery` over the local model, no resolver hit: top-1 identity, and a score above the floor minus a tolerance derived from the effective resolver boost plus an embedder-drift allowance
- oracle mode (`tests/nlp/fixtures.test.ts`) — exact reproduction of the committed file, and its invariants

`rank.ts` funnels every floating-point op through `Math.fround` and keeps vectors in `Float32Array`: a score is a function of the index's f32 values, which is what lets the goldens assert byte-equality. The emulation stays for that reason; removing it is a recorded follow-up (`nlp/NLP.md`).

## Theming

- CSS-variable based; `data-theme="dark" | "light"` on `<html>`
- Pre-paint script in `app.html` reads persisted choice / `prefers-color-scheme` before first render (no flash)
- Toggle widget writes `localStorage` and flips the attribute
- Shiki rendered with `themes: { light, dark }` so the same code-block HTML reacts to the toggle via CSS variables

## Hosting intent

- static SPA, no server; deploying is a follow-up — artifacts build locally and in the CI `nlp` job, nothing publishes them
- GitHub Pages first, Cloudflare Pages the alternative
- Pages hosts one site per repo, and `docs-zsh-core.yml` already claims it: the SPA takes the site root, the zsh-core docs move under `/zsh-core-docs/`, one deployment carries both
- before publishing:
  - `svelte.config.js` sets no `kit.paths.base`; the final URL decides
  - `THIRD_PARTY_NOTICES.md` — the bundle ships transformers.js, shiki and fonts; a real obligation, and this package has none of the user-facing docs its siblings carry
